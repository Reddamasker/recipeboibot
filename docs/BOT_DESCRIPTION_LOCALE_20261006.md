# Ручное описание и локализация — 6 октября 2026

Владелец изменил описание обоих ботов через BotFather, однако перед Start продолжал видеть прежний текст. Read-only API подтвердил getMe: recipeboi_test_bot (recipe_test) и Recipeboibot. В обоих default начинался «Что приготовить на ужин?», ru содержал прежний текст от 5 октября «Идеальный рецепт за 15 секунд», en и short description были пустыми. Причина — отдельная ru-версия, а не неуспешное ручное сохранение.

Сначала test, затем main выполнено setMyDescription(description='', language_code='ru'). Текст default не менялся. Проверены точное сохранение ручного default и пустое ru. По официальной семантике Telegram пользователи без отдельного языкового описания видят default. При сохранённом клиентском кеше надо заново открыть чат или перезапустить Telegram; удалять аккаунты, переписку или данные бота не нужно.

Резервы в постоянных томах: test /app/data/bot-description-ru-before-2026-10-06T11-20-45.721Z.json, main /app/data/bot-description-ru-before-2026-10-06T11-20-46.565Z.json. Токены не выводились. Новые сообщения не отправлялись, polling и квоты не менялись. MAX не затрагивался.

scripts/configure-bot.js теперь настраивает только команды и меню, не перезаписывает описания. scripts/update-bot-description.js --check читает текущее описание, --apply требует явный BOT_DESCRIPTION_FILE с новым текстом. При явной замене устанавливается default и удаляется ru-дубль, чтобы будущие правки default не скрывались за старой копией. Архивная экспортированная строка больше не используется как неявное значение для записи.

Это изменение метаданных и локальных CLI-скриптов: runtime src/public не менялся и контейнеры не перезапускались. Проверки — прямые getMyDescription до/после и node --check обоих CLI; apply без файла должен отказать до обращения к API.
