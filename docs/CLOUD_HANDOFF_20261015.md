## Продукт и пользовательская ценность

«Бот Рецепты» помогает быстро решить, что приготовить, учитывает продукты и вкусы, предлагает конкретные рецепты, сохраняет личную коллекцию и напоминает об ужине. Есть Telegram, MAX, Mini App, открытый веб-каталог и административный дашборд.

Основной сайт: https://dishfinder.ru; каталог: https://dishfinder.ru/recipes. Основной Telegram — `@Recipeboibot`, тестовый — `@recipeboi_test_bot`, MAX — `@id500912857935_bot`.

Ключевые возможности: подбор ужина, конкретный рецепт по запросу, предпочтения и аллергии, голосовой ввод, импорт текста/ссылок/фото/голоса/видео, коллекция, напоминания, подписка через Robokassa. Публичное предложение — 199 ₽/месяц, 7 дней бесплатно без привязки карты; реальные условия доступа проверять в актуальном коде и документации.

Для экрана продажи владелец выделил пользу: меньше времени на поиск, память предпочтений, свои любимые рецепты в подборе, заблаговременные напоминания. Мобильный интерфейс приоритетен. Согласованы сиреневые, сливовые и ягодные цвета, обращение на «ты», ясные кнопки Telegram/MAX, закрытие крестиком с возвратом к рецепту. Эмодзи в пользовательских текстах не использовать.

### Напоминания участникам триала

Запрос владельца: через N часов после начала триала приглашать добавить свой рецепт, затем повторять периодически. В чате **«Добавить рассылки участникам триала»** ход работы прерван; ответы на предложенный выбор расписания в доступной истории не обнаружены.

В локальном `main` есть два коммита, которых нет в проверенном `origin/main`. Для продолжения с телефона они 15 октября сохранены в отдельную удалённую ветку **`codex/trial-reminders-draft-20261015`**:

- `678f562` — механизм напоминаний, настройки, отписка, аналитика, MAX bridge v8 и тесты.
- `a86815d` — действие добавления рецепта продолжает работать при сбое аналитики нажатия.

Локальный HEAD и сохранённый draft: `a86815dad2c02cc5606636ce7fb73096c24a0f48`. Удалённый `main` проверен через `git ls-remote` 15 октября: `31169252042b37cfccb2ddb41188036db05b65e9`. Эти два коммита не входят в main и в ветку со сводкой. Их можно получить через `git fetch origin codex/trial-reminders-draft-20261015`; рабочий компьютер больше не нужен для получения исходников этой задачи. Черновик не означает проверенный или выпущенный продукт.

Документ локальной реализации — `docs/TRIAL_RECIPE_REMINDERS.md`; он явно отмечает, что публикации ещё не было. Выбранные в коде значения по умолчанию: через 24 часа, затем через 48 часов, максимум 3 сообщения; окно 10:00–20:00 по часовому поясу пользователя, иначе Europe/Moscow. Это реализационный выбор, не подтверждённый ответ владельца на вопрос о расписании.

Только новые триалы после запуска сбора; без заднего числа. Остановка при добавлении своего рецепта, завершении/отзыве доступа, переходе на оплату/промодоступ, отписке, лимите или неизвестном исходе отправки. Готовый рецепт из каталога не равен собственному импорту. Доставка не означает прочтение; результат измеряется в завершённом окне 24 часа после первой доставки. Повтор отправки при неизвестном исходе не допускается. Нужны полные проверки, реальное прохождение UI, выпуск test → Telegram → MAX, проверка bridge v8 и фиксация начала сбора. Не выдавать эту задачу за уже выпущенную.

## Правила разработки и выпуска

Node.js 24+, ESM, встроенный HTTP и `node:sqlite`, vanilla HTML/CSS/JS, внешних npm-зависимостей нет. Основные области: `src/telegram.js`, `src/server.js`, `src/db.js`, `src/dinner-*.js`, `src/importer.js`, `src/max-*.js`, `src/product-analytics.js`; интерфейс — `public/`, проверки — `test/`.

Локальный безопасный запуск: `node scripts/preview.js`, отдельная БД, без polling и реальных AI-вызовов. Проверки: `node --test --test-concurrency=1`. Не запускать вторую копию production polling; не сбрасывать пользователей, предпочтения, подписки или AI-учёт ради теста.

Изменения сценариев сразу включают аналитику входа, действия, результата, отказа/ошибки и ожидания. Переиспользовать имеющиеся события, проверять достижение через интерфейс, повторные отправки, скрытые экраны, фильтры и внутренние аккаунты. Не собирать тексты сообщений, поисковые фразы, продукты/аллергии, секреты или полные URL. Недоступные данные — не нули, D1/D7 — только зрелые когорты. Схема MAX bridge должна соответствовать новому агрегату. В локальной ветке уже v8 из неопубликованных напоминаний; это не доказательство версии рабочего MAX.

Обычный запрос «исправь» включает выпуск после проверок: `node scripts/deploy-test.js --check`, затем `--apply`; далее аналогично `scripts/deploy.js` и `scripts/deploy-max.js`. Обязательны резервные копии, проверка реально опубликованных файлов, агрегатов, целостности, сохранности окружений и данных. Явное ограничение «только test» действует до его отмены. После успешного выпуска сохранить общий код и отчёт в `main` и проверить отправку в `origin/main`. Нынешняя задача подготовки контекста не разрешает выпуск накопленных экспериментальных функций.

Проект уже работает на отдельном сервере; выключение рабочего компьютера не останавливает ботов. Актуальные рабочие базы и секреты находятся на сервере, GitHub хранит код. `.env.local`, SSH-ключи, расшифрованные архивы доступа и пользовательские данные в Git не включать. Платёжные ограничения владельца соблюдать строго по `AGENTS.md`; не предлагать альтернативы, которые он запретил.
