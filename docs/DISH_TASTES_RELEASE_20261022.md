# Единый экран вкусов — основной Telegram и MAX, 22 октября 2026

Владелец прямо разрешил перенос в основной бот: «Во всех сценариях, с сохранением лайков и дизлайков в профиле, как в тестовом». Прежнее ограничение test-only снято для этого экрана. По постоянному правилу общего пользовательского сценария обновлён и MAX.

## Поведение и границы

Перенесена проверенная реализация c6bb33e: один список компактных тегов блюд с настоящими фото, зелёный/красный/нейтральный выбор, поиск по 340 блюдам, уточнения по составу и способам приготовления. «Готово» закреплено внизу и доступно от трёх оценённых блюд. Старые списки заменены в знакомствах после trial/оплаты, необязательном руководстве, «Мои вкусы» под ужином и последнем шаге настроек семьи/времени/исключений. Остальные части анкеты и возвраты сохранены.

После «Готово» оценки хранятся в food_profiles.dish_ratings_json по стабильным ID и читаются с сервера при каждом открытии. При конфликте устройств клиент переносит только свои изменённые оценки на свежий профиль; независимые правки сохраняются. Ошибка связи оставляет черновик для повтора. «Позже» не сохраняет черновик и не стирает сохранённые оценки. Миграция добавляет столбцы; прежние точные названия блюд переводятся в ID без угадывания категорий, аллергии и другие настройки сохраняются. Дизлайк блюда не запрещает все его ингредиенты.

Каждый контур сохраняет свою базу и учётные записи. Перенос тестовых пользовательских данных в основной или объединение аккаунтов Telegram/MAX не выполнялись. Остальные тестовые варианты каталога, экрана продажи и авторизации не переносились. Отдельная новая логика автоматических напоминаний не входит в этот выпуск.

## Проверки

По 71 целевой проверке в обеих release-версиях: авторизация/изоляция, миграция, минимальные три оценки, два устройства, конфликт и идемпотентность, сохранность настроек, все 340 блюд и 4080 действий в смешанных историях, приоритет состава и способов, ранжирование и лимит фото. Общий редактор и 12 ключевых файлов логики совпадают между всеми тремя контурами.

Настоящий локальный UI с изолированными SQLite, без polling и внешнего AI, проверен в Telegram- и MAX-режимах. Заглушкой является только SDK мессенджера; запросы авторизации, чтения и сохранения идут через реальные API. Проверены 320/390/1280 px, видимость «Готово», два независимых браузерных контекста, одновременные правки, настройки → редактор → ужин → редактор, сбой сети и повтор. Ошибок JS/горизонтальной прокрутки нет. Физические приложения на телефоне не автоматизировались.

В обеих версиях реальные UI-события достигли БД: screen_view(taste), step_submit(taste), operation_finished(taste), client_error. В payload нет блюд, ингредиентов, поисковых фраз и оценок. Мобильные дашборды 320/390 показали обновлённую подпись шага без ошибок. Существующие тесты источников, внутренних аккаунтов, скрытых экранов и идемпотентности прошли в полных suite.
