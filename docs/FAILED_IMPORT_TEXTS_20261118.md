# Временные тексты неудачных импортов

Поручение владельца от 18 ноября 2026: сохранять тексты неудачных импортов, автоматически удалять и открывать только владельцу. Это ограниченное исключение из запрета хранения текстов сообщений. Старые исходники не восстанавливаются.

## Область и срок

Только обычный текст, отправленный на импорт из личного чата или формы Mini App Telegram/MAX. Непустой слишком короткий текст тоже учитывается. Фото, голосовые расшифровки, содержимое страниц по ссылкам, ответы AI, произвольные сообщения вне импорта и успешные импорты не собираются. Обработка событий и результата импорта прежняя; диагностическая ошибка не заменяет исходную ошибку пользователя.

Срок — 7 суток с первой ошибки. Повторы одного исходного текста этого аккаунта объединяются, увеличивают счётчик попыток, но не продлевают срок. После истечения запись недоступна сразу; физическая очистка работает при старте, каждом чтении/записи и каждую минуту работающего сервиса. После остановки сервиса просроченные записи удаляются при следующем старте. Успешный повтор того же текста, удаление аккаунта и кнопка владельца «Удалить сейчас» удаляют запись раньше.

Не более 12 000 символов, 20 записей аккаунта и 500 записей контура. При переполнении удаляются старейшие, есть счётчик. Полные HTTP(S)-ссылки и типовые явные ключи/пары секретов маскируются. Это не семантическая очистка всех возможных личных сведений, поэтому доступ строго ограничен.

## Хранилище и доступ

Отдельный файл `DATABASE_PATH.failed-imports/diagnostics.sqlite`, каталог 0700, файл 0600. SQLite secure_delete=ON и journal_mode=DELETE, без WAL. Штатные `storage.py`/backup.sh резервируют только основную recipes.sqlite, а исходники релиза не включают data; временные тексты не входят в эти копии. Копии диска сторонних провайдеров этой функцией не управляются.

Команда `/import_errors` в личном чате нужного бота показывает владельцу кнопку раздела. Mini App `view=import-errors`, API `/api/owner/import-failures`: действительная подпись и свежая авторизация нужной платформы, точное совпадение с `config.analyticsOwnerId`. Пароль/сессия дашборда, bridge-токен, внутренний тестовый аккаунт и preview-режим не дают доступа. В MAX собственный подтверждённый аккаунт владельца. Тексты не пересылаются через MAX bridge. В дашборде есть только инструкция открытия, без загрузки содержимого.

Ответы no-store, текст отображается как textContent без HTML, при скрытии/уходе страница очищается; повторное открытие запрашивает доступ снова. В журнале нет имён и внешних ID аккаунтов. Внутренний user_id нужен только для удаления при удалении аккаунта и не возвращается клиенту.

## Аналитика и проверки

Прежние import_jobs, step_submit, request_started, operation_finished, client_error продолжают измерять действие, результат и задержку. Новых дублей воронки нет. Отдельный диагностический отчёт показывает retained rows, captured attempts, expired/resolved/deleted/evicted и since. Это технический журнал всех импортов, включая проверки, а не конверсия рекламной когорты; фильтры источника рекламы и прежние исключения воронки не менялись. Дата начала сбора определяется отдельно в каждом контуре. При недоступности файла раздел выдаёт ошибку, не нули. Любая ошибка записи диагностик даёт только фиксированный сигнал `import_failure_diagnostics_unavailable`, без текста и идентификаторов.

Обязательные проверки: реальные отказы importText и успешный повтор, TTL без продления, очистка содержимого SQLite, дедупликация/лимиты, отсутствие текста в основной базе и общих отчётах, подписи и отказы обеих платформ, отказ доступа по cookie, удаление чужим аккаунтом, удаление аккаунта, экранирование HTML и открытие из Mini App. Продовые сообщения и AI-квота для проверок не используются.

Статус выпуска: подготовка и проверки.
