## Путь и поведение

Корзина недельного меню открывает выбор блюд по дням с отметками справа. «Далее» загружает ингредиенты выбранных блюд, фото/название, отдельное число порций и выбор строк. Можно снять выбор, вернуться к блюдам, переключить отображение г/мл и кг/л. Никаких предположений о плотности, объёме ложки/чашки или неизвестных порциях. Список меняется только после «Добавить»; отмена и предварительная загрузка его не меняют.

Ингредиенты из одного действия строки меню или карточки рецепта открываются сразу на втором шаге. Успешное добавление из меню ведёт в покупки, из карточки возвращает карточку с подтверждением. После закрытия формы с неподтверждённым сохранением общий повтор получает результат прежней операции и открывает покупки.

Новый список: закреплённый заголовок с отправкой/действиями, сворачиваемая горизонтальная полоса блюд, число продуктов, сортировка по категориям/названию/рецептам, категории с заголовками, количество под названием и отметка купленного справа. Нажатие продукта открывает действия, ручные позиции редактируются. Удаление блюда исключает только его вклад; остальные блюда и ручные записи остаются. В режиме сортировки по рецептам общий продукт выводится один раз в отдельной группе. Карточка источника позволяет изменить выбор и порции; исходные исключения сохраняются до явного изменения.

«Поделиться» использует системный выбор приложения, при его отсутствии копирует текст; если буфер недоступен, показывает выделяемый список. Системная передача не объявляется доставкой получателю. Сортировка и сворачивание относятся к представлению и не записывают workspace-команд.

## Данные и совместимость

`POST /api/workspace/groceries-preview` возвращает версию workspace и снимки состава выбранных записей меню либо одного доступного рецепта. Проверяются подпись платформы, разрешённый пользователь, private-test mapping, владение и доступ к рецепту. Endpoint только читает: без обновления `users.updated_at`, разблокировки первого рецепта, AI/квот/engagement. DTO не является подтверждением просмотра полного рецепта.

`groceries.fromPlan` принимает точные selections для entryIds, `groceries.fromRecipe` — ingredientKeys и recipeRevision. Порции списка не меняют меню. Выбор и рецепт проверяются до атомарной записи; конфликт версии либо изменившийся состав дают 409, форма блокируется до повторного открытия. Старые команды без selections совместимы. При потере ответа повтор использует прежний operationId и неизменный payload, исключая дубли.

Существующее объединение совместимых единиц остаётся серверным; категории только сортируют. Неизвестные количества не заменяются нулём. Прежние source без миниатюр читаются с fallback без миграции. Отдельные базы/настройки/ограничения платформ сохраняются.

Лимиты независимы: до 60 записей и до 400 ингредиентов рецепта, тело selections до 1,8 MB; общий сохранённый workspace по-прежнему не более 2 MiB. Одновременный максимум 60×400 может превышать общий бюджет: возвращается 413, запись целиком откатывается, форма остаётся доступной для выбора меньшего числа блюд. Уменьшение числа отмеченных строк само по себе не сокращает хранимые снимки источников.

## Аналитика

Сохранение и изменения используют прежние `workspace_view`, `workspace_action`, `workspace_saved`, UUID и подтверждения фактической видимости; новый selector не создаёт дополнительные сохранения. Preview и отправка списка учитываются отдельно как `workspace_interaction` с закрытыми kind/outcome, случайным flowId и временем. В событиях нет названий блюд, продуктов, дат меню, количества порций и текста списка. Preview не попадает в latency полного рецепта. Старые агрегаты без interactions означают недоступность данных. Определения и фактическая дата начала сбора фиксируются в ANALYTICS_CONTRACT после выпуска.
