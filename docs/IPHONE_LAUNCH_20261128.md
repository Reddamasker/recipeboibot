# Загрузка коллекции в Telegram на iPhone 28 ноября 2026

Владелец сообщил о двух iPhone с зависшей заставкой Telegram. В 16:47:08 МСК Nginx зарегистрировал один GET страницы /app с iPhone и три запроса ресурсов с ответом 200. Телефон по этим сведениям идентифицировать нельзя. В 16:47:34 монитор завершил цикл. На тот момент он проверял HTTP и polling, подтверждение первого экрана отсутствовало. На рабочем компьютере наблюдался также перемежающийся тайм-аут TLS. Причина отказа на каждом из двух устройств не установлена.

В версии aeb8469 первоначальные стили и сценарии Telegram доставляются одним сжатым документом. Сохранены порядок выполнения, авторизация контура, CSP с проверенными хешами и пути шрифтов. Формируется один кеш на процесс. Фотографии и данные профиля продолжают загружаться отдельно.

При повторных обращениях WebView iPhone без сигнала view-rendered дежурный монитор сообщает в настроенный личный чат при следующей проверке. Порог, ограничения и хранение описаны в ANALYTICS_CONTRACT.md. В тесте воспроизведены срабатывание, отсутствие дублей и снятие состояния. Доступность чата проверена через getChat. Тестовое сообщение в личный чат не отправлялось.

На прежней странице блокировка вторичных запросов CSS и JavaScript приводила к отсутствию коллекции и сигнала готовности Telegram. В WebKit с шириной 393 px при той же блокировке исправленная страница показала коллекцию, передала web_app_ready и view-rendered. Для проверки обоих опубликованных Telegram-документов и их CSP использовался отдельный локальный профиль и backend предпросмотра. Публичный рабочий адрес также проверен напрямую в WebKit без авторизации. Через независимый узел сжатый документ 156723 байта загружен за 0,31 секунды. Нативные устройства владельца недоступны для проверки.
