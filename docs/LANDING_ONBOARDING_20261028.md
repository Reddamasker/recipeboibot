# Сайт с рецептом перед ботом — 28 октября 2026

## Согласовано

Владелец согласовал план: поисковый посетитель ожидает сайт рецептов; неожиданный переход сразу в мессенджер может нарушать ожидание. Новый маршрут показывает полный рецепт до добровольного сохранения в Telegram/MAX. Сохранение и повторное открытие публичного рецепта бесплатны, trial включается только отдельным действием. Первое блюдо в боте повторно не выбирается; профиль не помечается заполненным.

План для телефона: https://docs.google.com/document/d/1wkwotu6Kugqjc_uXIfIQ531yTx6VB-e2_TEkedACnJc

Уточнение владельца во время реализации: задача включает саму рекламную кампанию Яндекс Директа. Текущие кампании проверяются отдельно; бюджет и распределение трафика запрошены. Публикация сайта не означает переключение рекламы или увеличение расходов.

## Реализация

- Новый адрес `/dinner`, полные рецепты `/dinner/:id`; фото, фильтры продуктов/кухонь и поиск используют общий каталог. Фильтры/возврат сохраняются. Первый экран сразу показывает блюда, без обязательной анкеты и окна продажи.
- Явное «Сохранить в боте» открывает выбор Telegram/MAX. Сервер выдаёт короткий непрозрачный код; успешная подготовка ссылки не объявляется сохранением. При ошибке рецепт остаётся доступен, есть повтор.
- Код связан с точным рецептом, анонимным потоком, известной рекламной меткой и целевым контуром; срок семь дней. Повтор подготовки не создаёт новую передачу для того же блюда/потока/платформы.
- Раздельные базы сохраняются. Запросы между фиксированными HTTPS-адресами контуров подписаны Ed25519, ключ каждого контура хранится в его БД; наружу доступен только открытый ключ. Отдельная устойчивая очередь повторяет подтверждения аналитики, не задерживая сохранение. Проверяются источник, адресат, время и привязка к исходной передаче. Пользовательские ID между контурами не передаются.
- Доверенная копия сохраняется без AI; отдельное разрешение относится к конкретному рецепту и владельцу. Личные правки ранее сохранённой копии сохраняются: исходный выбранный вариант при необходимости получает отдельный экземпляр. Повторы неизменённого рецепта используют прежнюю запись.
- Новый факт завершения первого рецепта отделён от настроек вкусов. При другом закрытом рецепте доступен только явно разрешённый публичный рецепт, коллекция и необязательные вкусы. Остальные ограничения доступа сохраняются.
- Существующая атрибуция первого запуска неизменяема; известная кампания и ценовое назначение сохраняются. Событие видимого рекламного входа не подменяется нажатием Save. Поздний приход события видимости связывается с прежней передачей.

## Аналитика

Полный контракт — `ANALYTICS_CONTRACT.md`. Повторно используются catalog_list/open/filter/search/empty и обычные события экранов/действий. Новые публичные этапы: catalog_save_intent, catalog_platform_selected, catalog_handoff_ready/error. Сервер подтверждает catalog_bot_started, catalog_recipe_saved/save_failed. Названия, состав рецептов, поисковые фразы, URL, токены и тексты в продуктовые события не входят.

Перед уходом в мессенджер ограниченная keepalive-отправка сохраняет прежние ID и не задерживает переход. Пропущенные клиентские этапы не восстанавливаются задним числом. Серверные подтверждения сохраняют исходное время при отложенной доставке. Анонимные потоки, аккаунты и рекламные клики имеют отдельные определения; новый блок не выдаёт поток за уникального человека. Доставка подтверждения в чат не считается чтением.

Основные показатели эксперимента: новые подтверждённые запуски на 100 рекламных кликов и стоимость запуска; далее trial и оплата при одинаковом завершённом окне. Вклад одного сайта не отделяется от добавленного выбора платформы и бесплатного сохранения. Сам мотив ухода статистикой напрямую не доказывается.
