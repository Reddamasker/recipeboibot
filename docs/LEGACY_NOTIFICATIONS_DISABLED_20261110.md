# Отключение старых подборок по расписанию — 10 ноября 2026

Причина обращения: основной @Recipeboibot отправил владельцу сообщение «Пора выбрать, что приготовить» в 17:20:14 МСК (14:20:14.316Z). Read-only проверка notification_deliveries подтвердила расписание Europe/Moscow 17:20 и отправки в предыдущие дни. Это обычное старое напоминание, не trial digest. При переработке интерфейса фоновый startNotificationScheduler продолжал запускаться, а прежняя настройка осталась в БД.

## Исправление

Старые подборки отключены по умолчанию общим LEGACY_DINNER_NOTIFICATIONS_ENABLED (в отсутствие явного true — false). Рабочие окружения не должны включать этот архивный режим без нового указания владельца. Совместимый код и его тесты сохранены, чтобы читать историю и старые рецепты; прежние расписания сами по себе не включают отправку.

Защищены запуск таймера, постановка в очередь, обработка старых очередей и повторов, непосредственная отправка напоминания и каждой части digest. Отключены автоматическое подключение к digest, его инициализация и восстановление приветствий. API сообщает enabled=false, available=false, nextDueAt=null и отклоняет включение с 410. Старый экран показывает отключение и переход в коллекцию; обновлён также общий bundle нового Mini App. Из приветствия trial убрано предложение настроить напоминания. Отдельное приглашение сохранить свой рецепт этим исправлением не меняется.

Пользовательские настройки, история рассылок, коллекции, подписки, trial и AI-учёт не сбрасываются. Прямой результат явного выбора старого рецепта не блокируется.

## Аналитика и проверки

Исторические notification_deliveries/trial_digest_* и даты начала сбора сохранены. Дашборд помечает показатели как историю отключённого сценария и сохранённые настройки, не активную рассылку. Новых событий/агрегатов нет, MAX bridge прежний. Отказ старому клиенту — прежний operation_finished(notifications), status=410 и длительность. Заблокированный цикл не создаёт доставок, просмотров, AI-вызовов или ложных ошибок.

Новая регрессия проверяет Telegram/MAX, отсутствие/false переключателя, старое активное расписание, queued/sent/chosen, незавершённую часть digest, новую активацию trial, повторные циклы и повторный процесс на той же БД. Снимки данных и исторические агрегаты неизменны, сетевой транспорт запрещён. Проверены API и достижение аналитического отказа с длительностью. Старые тесты расписания запускают явно включённый архивный режим; текущий тестовый сценарий ожидает 410.

Браузер Chrome 393×852: реальный старый клиент с тестовым SDK показывает отключение без переключателя и ведёт в новую коллекцию. screen_view(notifications) подтверждён в изолированной БД. Мобильный дашборд показывает новые подписи; ошибок JS нет. Нативные клиенты телефона не проверялись, реальные тестовые сообщения пользователям не отправлялись.
