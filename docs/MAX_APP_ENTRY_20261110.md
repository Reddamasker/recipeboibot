# Вход в приложение MAX без предварительного запуска чата — 10 ноября 2026

## Причина

Две реальные попытки входа 10 ноября в 14:29:38 и 15:16:31 МСК получили HTTP 403 на /api/me. Подпись MAX прошла проверку, аккаунт был создан, затем общий authenticate требовал is_allowed=1, который устанавливается при запуске чата. MAX допускает открытие Mini App без запуска бота. Клиент показывал сообщение о Start без кнопки продолжения. Источник конкретных переходов достоверно неизвестен.

## Исправление

Проверенная MAX-сессия открывает личное приложение независимо от is_allowed. Проверки подписи, срока, платформы и bot identity сохранены. Сам флаг не меняется: вход не создаёт acquisition_starts, подписку, trial или право доставки сообщений. Telegram сохраняет прежнее условие запуска чата. Уже созданные отказом аккаунты могут войти без сброса данных.

/api/me возвращает chatStarted; новый MAX-пользователь из базового URL попадает в коллекцию. Явные ссылки на рецепт, оплату и остальные экраны сохраняются. Ошибка входа предлагает повтор и рабочую ссылку в чат; повтор сохраняет текущий маршрут. Отправка собственного рецепта использует прежний collection_save с явной кнопкой перехода в чат.

Приветствие пробного периода в MAX остаётся pending без транспортных попыток до доверенной привязки чата. Ожидающие аккаунты исключаются до лимита очереди. После настоящего запуска доставка возобновляется, без изменения дат доступа и ложных ошибок.

## Аналитика

Прежние operation_finished(boot), auth_error, screen_view, workspace_view, step_submit(import) и workspace_saved покрывают путь. Подтверждённая личность определяется до дальнейших отказов доступа. Новый appEntry разделяет запросы входа, успешные аккаунты, видимые экраны, ошибки и время ответа. Начало app_entry_since фиксируется отдельно при запуске каждого контура, история не восстанавливается.

App-only аккаунты включены в общие продуктовые показатели отдельно от воронки стартов бота. До настоящего старта они не получают рекламную атрибуцию; их операции/оплата учитываются в продуктовых показателях, но не старой воронке bot-start. Анонимные ошибки доступны только без фильтра размещения: определить внутренний аккаунт до валидации нельзя. Старый MAX bridge без appEntry означает null, некорректный агрегат отклоняется.

## Проверки

Новые регрессии проверяют свежий и ранее отклонённый аккаунт, коллекцию/workspace, однократное сохранение, изоляцию данных, paywall без AI, поддельные/просроченные/чужие подписи, поздний первый Start, повторы, очередь приветствия и внутренний профиль. Отдельно проверены Telegram gate, read-only API и совместимость MAX bridge.

В Chrome на 320 и 393 px реальный интерфейс с тестовым SDK и изолированной БД прошёл: вход без Start → видимая коллекция → кнопка в чат, восстановление после 503, каталог → сохранение. События подтверждены сервером; новый блок дашборда отображается, ошибок JS нет. SDK MAX подменялся только в проверочном браузере; нативный клиент телефона не проверялся. Сообщения реальным пользователям и реальные AI-запросы не отправлялись.

## Выпуск

Готовится штатный test → Telegram → MAX с резервными копиями, проверкой работающих исходников, агрегатов и паритета. Фактическая ревизия, время и результаты полного прогона будут внесены после выпуска.
