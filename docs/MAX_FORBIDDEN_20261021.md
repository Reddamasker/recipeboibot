# Отказ доставки MAX и повторная обработка

20 октября 2026 в 21:15–21:19 МСК один входящий запрос в MAX обрабатывался восемь раз после HTTP 403 при обращении к API платформы. Ошибка транспорта не содержала status, поэтому журнал продуктовых операций показывал 500. Повторно пытались отправить и ответ, и сообщение об ошибке. Точная причина отказа в старой версии не сохранялась; блокировку бота пользователем не считаем установленной.

Исправление сохраняет безопасный тип транспортной ошибки. HTTP 403 становится окончательным failed для текущего события; попытки и исходные данные не сбрасываются. Контекст задачи запрещает новые сетевые обращения после 403, даже если вложенный обработчик перехватил ошибку. Повторная доставка webhook и перезапуск не возобновляют failed. Новое сообщение создаёт независимую задачу и может успешно обработаться после восстановления доступа. Сеть, 429, 5xx и остальные ошибки сохраняют прежний ограниченный механизм повторов. Запрет MAX не обходится, настройки и права бота не меняются.

Неуспешная доставка не учитывается как успешная и не создаёт просмотр рецепта. Прежний operation_finished содержит 403, дашборд уточняет смысл кодов чата; новых счётчиков и миграций нет. В журнале допускаются только классификация, ограниченный код платформы, метод и категория ресурса. Неизвестные коды превращаются в unknown, произвольные upstream message/body не сохраняются в ошибке. Исторические 500 не переписываются.

Проверки: настоящий обработчик /start через MAX worker, отдельная БД и искусственный транспорт; один сетевой вызов при 403, отсутствие ложной доставки, ровно одна операция 403, валидный агрегат и фильтр когорты, повтор webhook, перезапуск, успешное новое сообщение; 403 с не-JSON телом, отсутствие текстов/секретов в диагностике; повторы 429/503/сети и независимость параллельных контекстов. Реальные сообщения пользователям для проверки не отправляются.

Фактические результаты полного прогона и публикации будут дописаны после выпуска test → Telegram → MAX.
