## План и реализация

1. В кабинете владельца найден опубликованный «Твои рецепты», `@id500912857935_bot`. Существующий токен скопирован штатной кнопкой; сохранён только в игнорируемом `.env.max.local`. API `/me` подтвердил username и `is_bot=true`; ключ не выводился.
2. Проверены официальные API, события и MAX Bridge. Добавлены отдельный транспорт, постоянная очередь webhook с дедупликацией, привязки приватных диалогов и проверка владельца кнопок. MAX private chat ID не считается user ID; внешняя идентичность хранится как `max:<user_id>`.
3. Сохранена общая логика рецептов: предпочтения, конкретное блюдо, поиск и коллекция, первый рецепт, явный trial, диалог уточнения, фото/текст/ссылки/голос и напоминания. Вход MAX проверяется по подписанному initData; приложение использует MAX SDK и свои ссылки. Голос скачивается с проверкой публичного адреса, лимитами и фактической длительностью через ffprobe. Пересланные сообщения с `body=null` поддержаны.
4. Создан отдельный контейнер `recipeboibot-max`, SQLite volume, окружение и HTTPS vhost. Общие исходники сначала выпущены в тестовый Telegram, затем в основной и MAX. Свежее исправление дашборда `109b006` включено в объединённую версию.
5. Подписка webhook зарегистрирована и подтверждена через MAX API. В кабинете сохранены ссылка приложения и кнопка «Открыть». Проверка реального входа и рецепта из MAX-аккаунта владельца остаётся открытой: на момент проверки в новой базе пользователей и входящих событий не было.

## Ограничения первого запуска

- Оплата и автопродление MAX выключены. Третий контур того же магазина Robokassa требует отдельного merchant либо общего распределителя InvId и подписанной маршрутизации каналов. Нельзя включать существующие production-ключи в MAX: startup-проверка это запрещает. Первый рецепт и trial работают независимо.
- Получатель обратной связи MAX ещё не настроен (`MAX_FEEDBACK_USER_ID`). Обращения сохраняются в очереди, но доставка владельцу пока не подтверждена.
- Групповые чаты выключены. Вложения file/video получают явное пояснение; доступны текст, фото, аудио и ссылка. Прямой импорт видеовложения не добавлялся.
- Подписки, коллекции и предпочтения Telegram автоматически не переносятся в MAX. Совпадение числовых ID не связывает аккаунты.
- Настоящий SDK больше не ломает запуск из-за отсутствующего `expand()`. В обычном браузере без MAX-контекста SDK может предупреждать о недоступном native transport; это не подтверждение полноценной проверки WebView.
- Не объявлять полный живой паритет MAX завершённым до проверки владельцем `/start`, анкеты, результата, кнопок и Mini App внутри MAX. Для голосового ввода нужен отдельный настоящий voice smoke; AI-вызовы при локальных проверках не выполнялись.

## Дальнейшая работа

Использовать [штатный MAX deploy](MAX_DEPLOY.md): `node scripts/deploy-max.js --check`, затем `--apply`. Настройки и volume MAX сохранять отдельно. `scripts/configure-max-bot.js --check|--apply` выполняется в MAX-окружении; проверяет/регистрирует только нужный HTTPS webhook, без печати секретов. Общие изменения сопровождать паритетом Telegram test/main/MAX.

Официальные источники: [API](https://dev.max.ru/docs-api), [webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions), [MAX Bridge](https://dev.max.ru/docs/webapps/bridge), [валидация initData](https://dev.max.ru/docs/webapps/validation), [OpenAPI](https://github.com/max-messenger/api-schema), [сертификаты Госуслуг](https://www.gosuslugi.ru/crt).
