## Изменение сценария

- Пустая неделя: оригинальная иллюстрация проекта и две кнопки. После первой записи показаны все семь дней, в том числе пустые; дата/неделя закреплены при прокрутке, у каждого дня собственная кнопка добавления.
- Добавление: календарь с понедельника, переходы между месяцами, выбор месяца/года 2000–2099, четыре необязательных типа приёма пищи. Затем подборки → рецепты в двух колонках либо заметка. Без сохранённых рецептов доступен каталог внутри этого же сценария.
- Заметка — самостоятельная запись плана. Она не изменяет заметку рецепта, не получает выдуманные порции и не попадает в ингредиенты покупок.
- Свайп вправо раскрывает действие приёма пищи; для блюда доступны также дата, порции и замена рецепта. Свайп влево — приготовлено, покупки и удаление. Сам жест ничего не изменяет. Есть клавиатурная альтернатива и кнопка действий; вертикальная прокрутка и touch не конфликтуют.
- Приготовление относится к конкретной записи: одинаковый рецепт в разные дни имеет независимые отметки. Покупки из строки используют только эту запись; удаление сохраняет остальные дни и ручные продукты.
- Переход карточка → меню получает выбранные порции и возвращает в ту же карточку с видимым подтверждением. Кнопка составления меню сохраняет прежний рабочий автоплан из своих рецептов, с подтверждением и без перезаписи занятых слотов.

## Данные и аналитика

Расширен private workspace JSON, существующие записи читаются как `kind:recipe`, `cooked:false` без записи миграции и смены версии. Поддерживаются `kind:note`, `note`, `meal:null` и приготовление записи. Замена рецепта/типа сбрасывает его cooked, если новое значение не указано явно. Recipe→note удаляет только связанный источник продуктов; note→recipe автоматически покупки не добавляет. Выбор только заметок для `groceries.fromPlan` возвращает `422 PLAN_RECIPES_REQUIRED`; смешанный выбор обрабатывает рецепты.

Новые действия/поля аналитики не введены. Прежние `plan.add/update/delete/apply`, `collections.saveCatalog`, `groceries.fromPlan`, UUID, серверное и фактически видимое подтверждение; подписи дашборда уточнены до «записи меню». Названия, заметки, даты, типы и cooked в события не передаются. Схема MAX и `workspace_since` прежние; расширенный сценарий начинается с фактического выпуска test.
