# Один рецепт из нескольких фото — 28 октября 2026

## Поведение

В Mini App можно выбрать несколько фото или добавлять их по одному, проверить миниатюры, переставить страницы и удалить лишние. Один набор ограничен десятью изображениями JPEG/PNG/WebP и общим размером 6 МБ. Изображения не склеиваются и не уменьшаются: исходники передаются совместно с высокой детализацией. Для одиночного плотного фото сохранены увеличенные фрагменты.

В Telegram и MAX фото сначала попадают в черновик одного рецепта, включая одиночное фото. Пользователь присылает остальные части и нажимает «Собрать рецепт». Есть удаление последнего фото и отмена. Telegram PhotoSize остаётся выбором наибольшего размера одного снимка; разные сообщения и альбомы накапливаются. В MAX все изображения одного сообщения сохраняются, включая пересланные вложения. Черновик изолирован по владельцу коллекции, чату и отправителю; участник группы не управляет чужим набором.

Черновик содержит ссылки платформы и подписи, без скачанных изображений. Он доступен 24 часа после изменения; просроченные ссылки удаляются при обращении, запуске и каждые десять минут. Новый URL повторного файла обновляет ссылку без добавления страницы. Отмена сохраняет прежние ответы онбординга. Перезапуск основного процесса снимает блокировку прерванной сборки; диагностический импорт модулей её не снимает.

Устаревшая кнопка после изменения набора не запускает старый состав. Одновременные сборки заблокированы. Во время обработки новый снимок не добавляется молча: бот просит дождаться результата и прислать его снова. Дубликаты файлов исключаются по содержимому перед распознаванием. Повтор того же упорядоченного набора использует прежний import job и рецепт; изменение состава или порядка считается другим источником. Одиночные фото сохраняют совместимость прежнего ключа источника.

Извлечение проверяет все страницы, пропущенные/оборванные шаги, противоречия и принадлежность одному рецепту. Повторяющиеся строки в перекрытии не должны удваиваться; одинаковые продукты для разных частей блюда сохраняются. При неполном чтении допускается одна повторная AI-попытка, затем явный отказ без ready-рецепта. Черновик/форма сохраняются, можно добавить недостающее или повторить. Это проверка по доступному изображению, а не гарантия обнаружения отсутствующей страницы без видимых признаков пропуска.

## Аналитика

Контракт дополнен в ANALYTICS_CONTRACT.md. Существующие видимые screen_view(import), step_submit, operation_finished, request_started/request_visible и import_jobs сохранены. Новые серверные события photo_draft_started/cancelled имеют случайный ID набора; повтор не создаёт событие. image_count — аддитивная nullable-колонка, старые значения не восстанавливаются.

Новый необязательный photoImports содержит число задач из одного/нескольких фото, число изображений, текущие статусы, начатые и явно отменённые наборы чата. Отмена учитывается только для начала в той же когорте. assemblyTiming использует существующий operation_finished с числовым photoCount: время попытки сборки, включая повтор/ошибку; приём отдельного снимка в эту длительность не входит. Клиентское ожидание до видимого результата остаётся отдельно. Нет текстов, составов, URL, файлов или идентификаторов аккаунта в новых продуктовых данных. Фильтры когорты/источника и внутренних аккаунтов наследуются. Отсутствие раздела в старом MAX bridge означает недоступность; новая схема проверяет счётчики и квантили.
