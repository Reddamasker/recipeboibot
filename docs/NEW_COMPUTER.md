# Перенос проекта на другой Windows-компьютер

## Что уже работает

Бот `@Recipeboibot` и база работают на отдельном сервере `72.56.97.79`, приложение — https://recipes.spas-sky.ru. Выключение или переустановка старого компьютера их не останавливает. GitHub хранит код и контекст проекта; пользовательская база и рабочие секреты остаются на сервере.

## Скачать доступ на новом компьютере

После клонирования приватного репозитория новый Codex сам скачает зашифрованный архив доступа в Downloads через твою авторизацию GitHub:

```powershell
node scripts/download-access.js
```

Архив хранится в [приватном релизе GitHub](https://github.com/Reddamasker/recipeboibot/releases/tag/workstation-access-2026-09-25). Ключ переноса передаётся владельцу отдельно в исходном чате; в GitHub его нет. Передай новому Codex ключ. Он выполнит:

```powershell
node scripts/restore-access.js "$env:USERPROFILE\Downloads\recipeboibot-access.zip.enc" '<ключ переноса>'
```

Это создаст `recipeboibot-access.zip` рядом со скачанным файлом. Архив содержит действующий SSH-ключ и локальные API-настройки. Не загружай расшифрованный ZIP в GitHub и не отправляй его в общий чат. Для восстановления проекта и деплоя ничего со старого компьютера копировать не требуется. Сохрани возможность входа в свои аккаунты GitHub и ChatGPT: их пароли и сессии в архив не входят.

## Новое рабочее место

Установи Git for Windows, Node.js 24+ и приложение Codex/ChatGPT с поддержкой локальных проектов. Войди в свои прежние аккаунты. Docker на новом компьютере не требуется: контейнер собирается на сервере.

Открой PowerShell:

```powershell
git clone https://github.com/Reddamasker/recipeboibot.git
cd recipeboibot
node --version
node --test --test-concurrency=1
node scripts/preview.js
```

Открой http://127.0.0.1:3090/?view=dinner. Это тестовый пользователь в отдельной SQLite-базе. Предпросмотр не требует ключей, не запускает Telegram polling и не расходует AI-квоту: использует готовые рецепты. Для настоящей генерации используй работающий бот. Завершить предпросмотр: Ctrl+C.

Если приватный GitHub просит авторизацию, выполни обычный вход через Git Credential Manager. Не вставляй токены в URL репозитория.

## Восстановить SSH-доступ

Распакуй приватный архив в отдельную личную папку. В нём есть `ssh/id_ed25519`, `ssh/id_ed25519.pub`, `ssh/known_hosts` и `env.local`.

Помести ключи в `%USERPROFILE%\.ssh`. Если там уже есть ключи, сохрани переносимый ключ под другим именем (например `recipeboibot_ed25519`) и укажи его в пользовательском SSH config:

```sshconfig
Host 72.56.97.79
    User nikita
    IdentityFile ~/.ssh/recipeboibot_ed25519
    IdentitiesOnly yes
```

Не перезаписывай имеющиеся ключи, config или known_hosts. Запись сервера из архивного known_hosts добавь к существующему файлу. Проверенный fingerprint ED25519 сервера:

```text
SHA256:3AzEe68l3+T4SBdsvWrmtmSwDyPRLST3x2SUFdbaews
```

Проверка:

```powershell
ssh nikita@72.56.97.79
# После успешного входа: exit
node scripts/deploy.js --check
```

Если SSH отвергает права на приватный ключ, ограничь доступ к нему своей учётной записью Windows; не делай его доступным всем пользователям. Если ключ защищён паролем, загрузи его в SSH-agent перед запуском deploy: скрипт использует BatchMode.

`env.local` не нужен для деплоя или безопасного предпросмотра. Для отдельного тестирования реальных API можно скопировать его в корень проекта как `.env.local`. В переносимой копии polling отключён. Не включай его с рабочим токеном, пока рабочий бот запущен на сервере.

## Открыть проект в Codex

Добавь клонированную папку как локальный проект. Начни новый чат с этим сообщением:

> Продолжаем Recipeboibot. Прочитай AGENTS.md, docs/CODEX_HANDOFF.md, docs/NEW_COMPUTER.md и docs/CURRENT_DECISIONS.md. Проверь git status и тесты. Рабочий бот уже находится на nikita@72.56.97.79 в /opt/recipeboibot. Локально используй scripts/preview.js. Не сбрасывай данные пользователя и не запускай второй polling. Дальше задача: …

Контекст и правила сохранены в репозитории; копировать всю историю или папку `.codex` для этого проекта не требуется. Сам вход в аккаунт не является доказательством переноса локальных чатов. Официальные сведения о локальном состоянии: [Config and state locations](https://learn.chatgpt.com/docs/config-file/config-advanced#config-and-state-locations); установка приложения: [Desktop app](https://learn.chatgpt.com/docs/app).

## Обновить рабочий сервер

После изменений, тестов и коммита:

```powershell
git status
node scripts/deploy.js --check
node scripts/deploy.js --apply
git push origin main
```

`--check` только проверяет SSH и здоровье сервиса. `--apply` требует чистое Git-дерево, запускает тесты, упаковывает текущий коммит, загружает его по SSH, сохраняет зашифрованную копию БД, старые исходники и Docker-образ, затем пересоздаёт только recipeboibot. Проверяет Docker health и публичный HTTPS /healthz. При неудачной сборке/проверке восстанавливает прежний образ и исходники. Обратная миграция БД автоматически не выполняется: новые миграции должны оставаться совместимыми с предыдущим кодом.

Скрипт доставляет `src`, `public`, `Dockerfile`, `package.json`. Не изменяет рабочие `.env.local`, compose, nginx или Docker volume. Это обновление существующего сервера; для совершенно нового сервера см. README и deploy/*.sh. Удаление устаревших файлов из удалённого дерева не автоматизировано — если изменение требует такого удаления, его нужно отдельно запланировать. Архивы и Docker-образы не чистятся автоматически.

В БД остаются пользователи, коллекции, профили, история, запас ужинов, изображения и AI-квота. На сервере ежедневный зашифрованный backup; независимый offsite backup БД всё ещё не настроен. Его ключ `/opt/recipeboibot/backups/backup.key` находится на сервере и не включён в архив рабочего места.
