# ReciMe: визуальный тест Telegram, 9 ноября 2026

## Граница задачи

Владелец попросил повторить четыре присланных экрана ReciMe с палитрой проекта и разместить результат только в тестовом Telegram-боте, **без перезапуска контейнеров**. Это визуальный тест интерфейса, а не выпуск серверных функций календаря и покупок. Основной бот и MAX не обновляются.

Новый вход: `/review/recime-20261109/index.html?view=collection`. Прежний `/` и старые кнопки сообщений остаются прежними. Работающий Node кеширует собранный корневой HTML вместе с ресурсами; новый статический путь читается с диска. Обычный `deploy-test.js --apply` останавливает контейнер и для этой задачи не используется.

## Интерфейс и данные

- Геометрия проверена при ширине 393 CSS px и высоте 807 px: начало поиска и мозаик, вытянутая сетка 174/206, фиксированная нижняя панель и кнопка добавления. Нативная строка состояния телефона и шапка Telegram не имитируются.
- Палитра: фон `#f3f0f7`, текст `#302537`, акцент `#a4415c`, вторичные поверхности `#e7def0`, белый контент. Русский интерфейс без эмодзи.
- Кириллические Inter, Bitter, Marck Script и Lobster размещены локально с OFL. Закрытые шрифты ReciMe не копировались. Иллюстрации календаря и покупок выполнены в SVG по композиции референсов.
- Recipes читает настоящую личную коллекцию через существующий `/api/library`. Подборки показывают существующие теги; отдельного хранения книг пока нет. Данные в browser storage не подменяют серверную коллекцию.
- Импорт, личный рецепт, профиль, доступы и готовка используют прежние компоненты и API. Изолированный bundle содержит снимок общего клиентского кода; общие `app.js`, `styles.css`, backend не менялись.
- Discover использует настоящий `/api/catalog`. Деталь открывается общим `RecipeDetail`; готовка публичного рецепта не пишет фиктивное принятие или приготовление. Сохранение ведёт в действующий публичный сценарий. Авторские рейтинги и числа сохранений не выдумываются.
- Meal Plan и Groceries показывают пустые состояния. Нажатия объясняют, что серверное сохранение будет подключено отдельно; запросов сохранения меню/списка нет. Настоящее содержимое коллекции и все данные аккаунтов сохраняются.

## Аналитика

Вопрос теста — достижимы ли новая оболочка и прежние операции без изменения доступа. Единица — видимый экран или действие авторизованного аккаунта. Отдельный продуктовый эффект меню и покупок не заявляется.

Используется прежняя очередь `public/analytics.js`: прежние ID повторов, 80 записей, ограниченные повторы, ошибки и фильтры источника/внутренних аккаунтов. Recipes — `screen_view(collection)`. Три новых раздела — `screen_view(other)`; в текущем дашборде они **не различаются**, это ограничение тестового ревью. Подтверждённая публичная деталь — `screen_view(recipe)` без signed receipt личной коллекции. Явный поиск — прежние `step_submit`, `request_started`, `request_visible` для `other`; отказы — прежний `client_error`. Импорт и личный рецепт сохраняют свой полный существующий учёт. Демонстрационные кнопки не регистрируют успешное сохранение данных.

Не добавлены новые события, шаги, агрегаты или схема MAX bridge. Показатели дашборда и общая дата начала сбора прежние. Новый тестовый вход начинает создавать наблюдения только после фактической публикации; старые просмотры не восстанавливаются. Тексты запросов и продукты в private analytics не передаются. События `catalog_*` в private очередь не отправляются. `plan_selected` относится к тарифу и для меню не используется.

## Публикация

Новый `scripts/deploy-test-review.js --check`, затем `--apply` выполняет штатный read-only `deploy-test.js --check`, полный `node --test --test-concurrency=1`, manifest SHA-256, отдельный архив, locks и backup меню. Копируются только новые файлы namespace, HTML последним. Проверяются байты в контейнере, на хосте и по HTTPS. Затем меняется только default menu button `recipeboi_test_bot` и перечитывается результат.

Сверяются ID/PID/StartedAt/RestartCount/image всех трёх контейнеров, хеши всех защищённых `src/public` вне нового namespace, `.env.local` и compose; health/ready и read-only SQLite integrity/foreign keys. Секреты не выводятся. Сохранённая команда отката возвращает прежнее меню без удаления данных.

Hot-static ревью сохранено и на хосте, но не является пересборкой образа. Следующий обычный запуск polling может восстановить старую кнопку из APP_URL; повторное создание контейнера потребует включить этот каталог в образ. Индивидуальное меню чата может перекрывать default.
