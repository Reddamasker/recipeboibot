# Выбор рецепта в воронке — 6 октября 2026

По поручению владельца добавлен этап «Выбрали рецепт»: явный выбор блюда из предложенных вариантов. Используется первое сохранённое recommendation_accepted/dinner_recommendation_accepted, first_recipe_selections.source=dinner и исторический selected_id с временем завершения первого результата. Просмотр списка, генерация, запрос конкретного блюда и импорт не создают выбор. Источники дедуплицируются по аккаунту; фильтры владельца, Альбины, служебных и повторных рекламных пользователей сохранены. Серверные пользовательские данные не переписываются.

Новый selectedRecipe присутствует в верхних карточках, последовательной воронке, конверсиях и таблице рекламных меток. Последовательный путь: Start → результат подбора → выбор → trial → оплата. Trial/оплата без предыдущих действий остаются в независимых totals; исторические trial без зафиксированного выбора не подменяются вымышленным выбором. Карточка «Первый рецепт» переименована в «Результат подбора», поскольку прежняя метрика включает показ вариантов и не доказывает открытие полного рецепта. Поле firstRecipe сохранено для совместимости, ценовой отчёт сохраняет прежнюю методику независимых этапов.

MAX передаёт новый этап через защищённый агрегат версии 2. Устаревший/некорректный агрегат или сбой сохраняют рекламные показатели и обозначают неизвестные этапы, а не нули. Общий режим складывает аккаунты платформ; это не дедупликация людей между Telegram и MAX.

Проверки охватывают просмотр без выбора, повторные события и запись выбора в нескольких таблицах, временной порядок, рекламные метки, исключения и передачу/сбой MAX. Проверки используют отдельные SQLite и заглушки, без production polling и реальных AI-запросов.

Фактический выпуск и серверная проверка фиксируются после штатных --check/--apply test → main → MAX. Рекламные кампании, бюджеты, тексты ботов и сценарий trial не меняются.
