# Согласование регулярных платежей Robokassa

3 октября 2026 поддержка ответила в обращении «Подключение рекуррентных платежей для магазина Myrecipies». Статус «Выполнен» не является одобрением. Требуются цена и описание услуги, подробная оферта, отдельное изначально не отмеченное согласие на регулярные списания/обработку данных/оферту, понятные сумма/период/дата, история согласий. После подготовки нужно ответить в обращении с идентификатором магазина. Без согласования ошибка 34; тестовая среда не позволяет проверить рекуррентные платежи.

Подготовлено: полный текст согласия и ссылки на offer.html#auto-renew / privacy.html; единый серверный текст условий для каждого срока; проверка актуальной версии согласия на сервере; payment_consent_history с пользователем, заказом, временем, суммой, периодом, текстом, версией и полными копиями юридических документов с SHA-256. Повторное подтверждение и отзыв записываются отдельными строками, прежние записи не переписываются. Карточные реквизиты, IP и User-Agent не сохраняются. Privacy описывает историю; существующее условие отдельного хранения договорных сведений при удалении профиля сохранено. История не связана каскадным удалением с профилем.

В действующем экране «Подписка и оплата» добавлены сумма/дата автопродления и отмена. Отмена не отнимает оплаченный доступ; поздний callback первоначального заказа не включает автопродление повторно. Реальный транспорт Merchant/Recurring заблокирован в тестовом режиме/контуре даже при включённом флаге: IsTest не является защитой для повторного списания. Unit-тесты используют только внедрённый mock transport.

Проверка локального scripts/preview.js: отдельная БД, dummy платёжные ключи, polling/AI отключены, HTTPS запросы браузера заблокированы. Фактический экран оплаты на 320/390/1280 px без переполнения, галочка не отмечена, создание заказа с согласием и отмена успешны, ошибок JS нет. Снимки: data/offer-recurring-audit/consent-*.png. Реальные платежи не проводились.

Флаг ROBOKASSA_RECURRING_ENABLED в рабочих контурах не включать до одобрения и согласованной контрольной оплаты. Подготовка к согласованию не означает активацию услуги.
