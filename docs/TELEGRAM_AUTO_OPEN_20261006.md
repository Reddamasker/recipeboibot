# Проверочная ссылка автоматического открытия Telegram — 6 октября 2026

Владелец запросил ссылку для проверки на телефоне без дополнительного нажатия на промежуточной странице.

Новый отдельный маршрут: https://dishfinder.ru/open/telegram. Сервер выбирает username текущего контура и start=dinner. Клиент автоматически пытается открыть tg://resolve, а через 1,8 секунды переходит на соответствующий t.me, если страница остаётся видимой. Уход страницы в фон, pagehide и ручной запасной переход отменяют таймер; возвращение из приложения не запускает повторное открытие. Вкладка, открытая в фоне, ждёт первого показа. Без JavaScript работает переход через t.me.

Адрес test: https://recipeboibot-test.89-223-123-75.sslip.io/open/telegram. Открывает recipeboi_test_bot. Основная ссылка открывает Recipeboibot. Проба без campaign не создаёт рекламных событий. Для будущей рекламной проверки параметр campaign использует существующее размещение и создаёт отдельный ad_ на каждое обращение с сохранением UTM/yclid. HEAD и известные предпросмотры не создают клики. Произвольные адреса назначения не принимаются.

Текущие /go/ и /landing/go/, объявления и бюджеты не меняются. MAX получает общий код, но маршрут Telegram там возвращает 404. Окружения, базы, ограничения платформ и AI-учёт сохраняются.

Автоматическая попытка не гарантирует открытие приложения: браузер может показать подтверждение или запретить внешнюю схему. Кнопка «Начать» в Telegram остаётся. Работа на реальном телефоне требует проверки владельцем; успешный HTTP или VM-тест не означает успешного запуска приложения.

Проверки: клиентские сценарии автоматического запуска, отказа схемы, запасного перехода, ухода в приложение и возвращения; HTTP проверки отсутствия ложных рекламных событий, сохранения меток и прежнего 302; полный node --test --test-concurrency=1. Фактический выпуск фиксируется ниже после штатных --check/--apply test → main → MAX и проверки паритета.
