# Вход в Telegram по красивой кнопке — 6 октября 2026

После теста автоматического перехода с системным подтверждением владелец поручил попробовать страницу с красивой кнопкой, открывающей Telegram и передающей стартовый параметр.

Отдельный вариант: https://dishfinder.ru/open/telegram/button. Основная кнопка «Подобрать ужин в Telegram» использует tg://resolve?domain=Recipeboibot&start=dinner. До нажатия страница не открывает приложение и не включает таймер. Открытие выполняется синхронно в обработчике нажатия; через 1,8 секунды работает запасной t.me, если страница остаётся видимой. Уход в приложение отменяет переход; возвращение не запускает приложение повторно, но новое нажатие позволяет повторить попытку. Без JavaScript работают нативная ссылка кнопки и отдельная HTTPS-ссылка.

Тестовый адрес: https://recipeboibot-test.89-223-123-75.sslip.io/open/telegram/button. Бот выбирается по контуру. Параметр campaign поддерживает отдельный ad_ для каждого обращения, сохраняет UTM/yclid и общую атрибуцию. Проба без campaign не записывает рекламный клик. MAX получает общий код и возвращает 404 на обоих Telegram-маршрутах.

Оформление использует существующее фото ужина и палитру проекта: бумага, графит, оливковый, сиреневый. Без эмодзи и неподтверждённых обещаний скорости. На странице явно написано, что в Telegram надо нажать «Начать»: обычная deep link не отправляет /start за пользователя. Системное подтверждение браузера по-прежнему возможно.

Старый автоматический /open/telegram, существующие /go/ и /landing/go/ сохраняются. Объявления, бюджеты, базы, настройки оплаты и AI-учёт не меняются.

Проверки: клиентские сценарии ожидания кнопки, прямого открытия в событии нажатия, повторной попытки после возвращения, отказа схемы и сохранения рекламных меток; HTTP обоих режимов; визуальная проверка 390 и 320 px. Скриншоты сохранены локально в outputs/telegram-button. Выпуск фиксируется после штатных --check/--apply test → main → MAX и проверки паритета.
