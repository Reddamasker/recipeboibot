# Восстановление приёма Telegram 27 ноября 2026

26 ноября в 10:55 МСК Nginx на транзитном узле не запустился после ошибки DNS при разрешении api.telegram.org. Служба имела Restart=no. В 21:26 МСК основной бот получил ECONNREFUSED при настройке меню. Повтор запросов действовал только внутри цикла получения обновлений. Ошибка запуска попала в журнал, HTTP-сервер продолжил работу, а readyz проверял только готовность платёжных настроек.

27 ноября шлюз восстановлен после nginx -t. Для nginx.service на транзитном узле установлен /etc/systemd/system/nginx.service.d/recipeboibot-retry.conf с Restart=on-failure и RestartSec=30s. После запуска штатных Telegram-контейнеров отложенный импорт перешёл в ready в 13:48 МСК.

Выпуск 7fd3fe1 повторяет инициализацию после отказа, сохраняет проверку имени тестового бота и подтверждает готовность Telegram только после успешного getUpdates. При ошибке получения обновлений readyz возвращает 503 до восстановления. Монитор опрашивает этот адрес. Регрессионная проверка имитирует отказ первого запроса меню.

Исправление опубликовано по порядку в Telegram test, основной Telegram с сайтом и MAX с резервированием. Полный локальный прогон и серверные проверки завершились без ошибок. Пропущенный локально тест Python-валидатора отдельно успешно выполнен с установленным Python.
