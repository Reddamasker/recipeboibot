# Напоминания добавить свой рецепт во время триала

Локальная подготовка 14 октября 2026. Публикация пока не выполнена.

По умолчанию: первое сообщение через 24 часа после старта триала, следующие через 48 часов после предыдущей попытки; максимум три сообщения. Отправка только с 10:00 до 20:00 в часовом поясе настройки напоминаний об ужине, при его отсутствии — Europe/Moscow. Просроченные интервалы не догоняются пачкой. В цепочку входят только триалы, начавшиеся после первого запуска новой версии. Уже существующие триалы не получают задним числом новую рассылку.

Сообщение: «Сохрани свой любимый рецепт. Пришли ссылку, фото, текст или голосовое с рецептом — соберу ингредиенты и шаги в карточку. Она останется в „Моих рецептах“, чтобы не искать её снова». Кнопки: «Добавить свой рецепт», «Не напоминать об этом». Первая открывает существующий сценарий /save и сохраняет предыдущий контекст диалога; вторая навсегда останавливает эту цепочку для аккаунта.

Остановка: уже есть собственный рецепт (text/url/image/audio/manual), закончился или отозван доступ, началась платная подписка или промодоступ, достигнут лимит, отключение пользователем, ошибка адресата или неопределённый исход отправки. Сохранение готового рецепта из каталога или генерации не считается добавлением своего рецепта. Внутренние виртуальные тестовые профили и их владельцы не включаются автоматически. Telegram и MAX используют один механизм, отдельные базы и адресацию платформ.

## Настройки

Настройки хранятся в `trial_reminder_settings` каждой базы и переживают выпуск. CLI из нужного контура:

```sh
node scripts/trial-reminders.js
node scripts/trial-reminders.js 24 48 3 on
node scripts/trial-reminders.js 24 48 3 off
```

В контейнере, где scripts не включены в образ, тот же доверенный API доступен через импорт `src/trial-reminders.js` и `configureTrialReminders`. API не доступен пользователю по HTTP. Задержка 1–144 часа, периодичность 24–168 часов, лимит 1–7. Новая начальная задержка применяется к новым участникам; уже назначенная ближайшая отправка сохраняется, новые интервалы применяются после следующей попытки. Выключение останавливает отправку. Локальный `scripts/preview.js` планировщик не запускает.

## Надёжность

Случайный ID доставки и уникальная пара аккаунт/номер сообщения. Захват и перенос следующего срока — одна SQLite-транзакция. Повтор цикла или перезапуск не переотправляет уже захваченное сообщение. Неизвестный исход сети не считается доставкой и останавливает цепочку. Оборванная процессом попытка спустя две минуты получает unknown; сама попытка не повторяется. Максимум 20 отправок за цикл. Ни текста пользователя, ни ответа провайдера, ни URL в журнале доставки нет. Удаление аккаунта удаляет связанные записи каскадно.

## Аналитика

Источник входа — `user_trials`, участия — `trial_reminder_members`, доставки и действий кнопок — `trial_reminder_deliveries`, результата — существующая `recipes`. Ошибки/успех самого импорта остаются в существующих `import_jobs` и `operation_finished` шага import. Новые дублирующие продуктовые события не вводятся.

Дашборд: «Действия, качество и потери» → «Триал: приглашение добавить свой рецепт». Считает участников, подтверждённые доставки и аккаунты, уникальные нажатия на сообщение, отписки, ошибки, неизвестные исходы и отправляемые попытки. Задержка доставки измеряется от назначенного срока, время до нажатия — от подтверждённой доставки. Чтение чата не наблюдается. Скрытые страницы и загрузки API не создают показов/нажатий этой цепочки.

Результат: добавленный свой рецепт в течение 24 часов после первой подтверждённой доставки. Знаменатель — аккаунты, для которых эти 24 часа уже завершились. Это наблюдаемая последовательность, не причинный эффект рассылки. Сохранённая/архивная карточка остаётся свидетельством добавления; удаление аккаунта удаляет его историю. Платформы разделены, фильтры аккаунтов/размещения и исключения берутся из общей воронки. Пустой знаменатель даёт null, а не 0%. Новая схема MAX bridge v8 требует новый агрегат; несовместимая версия показывает недоступность.

Начало сбора — `trial_reminder_settings.started_at` каждой базы при первом запуске новой версии. Исторические доставки не восстанавливаются. Фактические времена начала в рабочих контурах нужно зафиксировать после выпуска.
