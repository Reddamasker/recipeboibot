# История пользователей и рекламных входов — 10 ноября 2026

Поручение владельца: видеть у конкретного пользователя объявление, его поисковый запрос, если Яндекс его предоставил, и последний достигнутый шаг. Изменение общее для тестового Telegram, основного Telegram и MAX.

## Реализация

- Защищённый дашборд: блок истории пользователей, отдельные платформы, фильтр кампании, даты первого появления и поиск аккаунта, страницы по 10 записей. Хронология, ошибки, длительность, сохранения, импорт, trial и оплата берутся из существующих событий и серверных результатов.
- Первая связь со случайной рекламной меткой сохраняется после проверки подписи Mini App или настоящего старта чата. MAX app-first не создаёт фиктивный старт и не получает право на сообщения. Передача метки может отсутствовать в нативном клиенте; такой вход остаётся без источника.
- Метрика получает только случайный ID публичного посещения; её ClientID сохраняется у нас для точного сопоставления. Ошибка/отсутствие SDK не мешает переходу. Личные экраны, внутренние посещения и тексты бота не передаются.
- Директ возвращает ID объявления и доступные текущие тексты. Для комбинаторных объявлений отображаются варианты заголовка, а не выдуманный точный показ. Длинные ID сохраняются без потери цифр.
- Импорт поисковой фразы реализован с точным сопоставлением визита, браузера, кампании и объявления. Несколько визитов/меток, сэмплирование или несовпадающие ID не дают персонального запроса. Ключевая фраза никогда не становится поисковым запросом.

## Доступ к Метрике

На проверке прежний YANDEX_DIRECT_TOKEN получает HTTP 403 access_denied от Reports API; отдельного YANDEX_METRIKA_TOKEN нет. Счётчик 114158743 уже установлен и привязан к кампании. Для автоматического импорта нужен отдельный OAuth с единственным правом metrika:read и доступом к этому счётчику. Новое разрешение запрошено у владельца отдельно; наличие браузерной сессии не считается серверным API-доступом. До подключения поле явно показывает «Нет доступа к запросам Метрики» либо отсутствие связи визита.
