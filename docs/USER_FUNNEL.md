# Воронка пользователей

Владелец запросил 2 октября 2026 цепочку: реклама → переход → запуск → первый рецепт → триал → оплата. Отчёт доступен только Telegram-аккаунту владельца (`ANALYTICS_OWNER_ID`, по умолчанию 6971956699). Оба контура используют один код и отдельные данные.

## Использование в личном чате бота

- `/funnel` — общие числа за всё время, включая органические запуски.
- `/adlink kanal_oct Канал, октябрь` — создать отдельную ссылку для размещения. Повторная команда возвращает ту же ссылку.
- `/funnel kanal_oct` — воронка новых пользователей этого размещения.
- `/adstats kanal_oct 15000 12000` — записать общие показы и охват из статистики площадки. Охват необязателен. Повторный ввод заменяет итог, не прибавляет его.

Для каждого размещения используйте новую ссылку, выданную `/adlink`. В основной среде она имеет вид `https://recipeboibot.89-223-123-75.sslip.io/go/kanal_oct` (текущий APP_URL); `https://dishfinder.ru/go/kanal_oct` ведёт в тот же основной бот. Тестовый бот выдаёт ссылку своего домена.

## Что считается

Показы и уникальный охват берутся из рекламного кабинета или статистики публикации. Автоматической интеграции с площадкой нет: источник рекламы пока не указан владельцем. Неизвестные значения обозначены «нет данных»; ноль не подставляется. Общий охват разных размещений не складывается, поскольку аудитории пересекаются.

Переход — GET к зарегистрированной ссылке `/go/:slug`, за которым сервер выдаёт 302 в Telegram. HEAD, известные preview-боты и prefetch не учитываются. Открытие Telegram и просмотр чата отдельно подтвердить нельзя. Повторные переходы считаются запросами; это не уникальные люди. Неизвестные сканеры могут увеличивать счётчик. Исторические клики до подключения не восстанавливаются. IP, User-Agent и cookie для этой аналитики не сохраняются.

Каждый переход получает случайный token в параметре `/start ad_<token>`. Первый зарегистрированный `/start` связывает пользователя с размещением; повторные команды не меняют источник. Ранее запущенные аккаунты считаются повторными посетителями и не входят в новую рекламную когорту. Общий отчёт включает исторические `is_allowed=1`, но не выдумывает дату их первого Start. Конверсия переход → запуск использует число различных переходов с новым Start, чтобы пересылка одной Telegram-ссылки нескольким людям не давала больше 100%.

Первый рецепт — успешный готовый рецепт в коллекции (включая позднее архивированные), конкретный рецепт в `recipe_suggestions`, успешный `first_recipe_results` либо фактически показанная рекомендация ужина. Черновики, ошибки и незавершённая генерация не учитываются. Считается получение результата, не факт приготовления. Для новых first_recipe_results сохраняется completed_at; старые данные используют доступное время начала.

Триал — серверная запись `user_trials`; повторная активация и истёкший trial не меняют факт прохождения этапа.

Оплата — `payment_orders.status='paid'`, `paid_at` и `is_test=0`. Новые initial/recurring заказы сохраняют режим при создании. Заказы тестового контура и режима провайдера помечаются `is_test=1`; старые заказы без отметки (`NULL`) показываются отдельно и не объявляются настоящими продажами. Промодоступ, ручная подписка и mock_payments не считаются оплатой. Повторный callback и повторная покупка не увеличивают число оплативших пользователей.

Последовательная цепочка требует прохождения этапов по времени: Start → рецепт → триал → оплата. Отдельная строка показывает всех достигших каждого этапа, включая тех, кто пропустил trial или активировал его до первого рецепта. Проценты внутренних этапов относятся к предыдущему этапу цепочки. Общий Start включает органику, поэтому процент из рекламных переходов доступен только отдельному размещению.

Аккаунт владельца и private-test-профили исключены из пользовательских чисел. Удаление аккаунта каскадно удаляет персональную атрибуцию; анонимные переходы сохраняются. Отчёт относится к сохранившимся аккаунтам, а не к пожизненному числу всех удалённых пользователей.

## Технический доступ и проверка

`node src/admin-funnel.js [код]` выводит JSON. `GET /api/admin/funnel?campaign=код` требует подписанный Telegram initData и проверяет реальный Telegram ID владельца, независимо от private_test_profiles. Публичного доступа к отчёту нет.

Аддитивные миграции: acquisition_campaigns, acquisition_clicks, acquisition_starts, acquisition_metadata; payment_orders.is_test; first_recipe_results.completed_at. Пользовательские данные, сроки доступа и AI-квота не сбрасываются; модели, интерфейс пейволла и его несогласованный макет не меняются.

Автотесты проверяют атрибуцию, повторы, последовательность, подписанный платёжный callback, ошибки генерации, отдельный подсчёт тестовых/неизвестных оплат, отсутствие доступа посторонних, preview-запросы и удаление аккаунта. Статус выпуска фиксируется после фактической публикации.
