# Меню и покупки из пустой коллекции — 9 ноября 2026

## Причина

После первого функционального выпуска владелец сообщил: меню не добавляется, покупки не заполняются. В его тестовом аккаунте нет сохранённых рецептов. Кнопки меню/покупок показывали только «Сначала добавь рецепт» и «Понятно», а сохранение Discover открывало сайт. Предыдущие проверки на заполненной библиотеке и серверная проверка ручных покупок не покрывали этот тупик. Работающий API сам по себе не означал завершённый сценарий нового пользователя.

## Исправление

- Пустая коллекция: добавление блюда сразу открывает выбор из каталога, с поиском и страницами. После сохранения — явное продолжение к дате, приёму пищи и порциям.
- Автоплан: можно выбрать несколько блюд каталога, сохранить и проверить их распределение по дням перед добавлением. Это готовые рецепты, без новой AI-генерации.
- Покупки: каталог доступен напрямую и через действие «Из сохранённого рецепта» при пустой библиотеке. Из меню продукты добавляются отдельным явным действием. Ручные позиции сохранены.
- Discover: сохранение теперь происходит в приложении; выход на сайт не требуется.
- Потерянный ответ после записи: повтор с тем же UUID работает в открытом выборе, после его закрытия и на Discover. Личная библиотека обновляется без перезагрузки. Независимый review выявил и помог закрыть два последних случая.

Команда `collections.saveCatalog` использует доверенный каталог и прежние grants. Сохранение рецепта, grant, workspace version и журнала операций — одна транзакция. Не создаёт дубль при повторе, не запускает trial, не вызывает AI, не открывает другой закрытый личный рецепт. Никакие демонстрационные блюда в аккаунт владельца автоматически не добавляются.

## Аналитика и проверки

Прежние `workspace_view`, `workspace_action`, `workspace_saved`; добавлено ограниченное действие `collections.saveCatalog` в `collections`, подпись в дашборде. Видимое подтверждение в диалоге наблюдается на самом тексте, после закрытия/повтора — на toast. Поиск использует существующие `step_submit/request_started/request_visible(other)`. Имена блюд и поисковый текст в private события не передаются. Старый MAX-агрегат без нового действия принимается без выдуманного нуля; прежняя дата начала workspace-сбора сохраняется.

API Telegram/MAX: пустая библиотека → trusted save → меню → покупки; replay/новый UUID; invalid input; чужой рецепт; rollback; прежняя блокировка личного рецепта; отсутствие AI/trial. Локальный Chrome на отдельной БД без polling/AI: весь путь с нуля, ручной выбор и три блюда автоплана, покупки из рецепта/меню, перезагрузка, inline сохранение Discover, 320/393/430 px.
